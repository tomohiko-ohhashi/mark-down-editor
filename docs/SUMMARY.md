# 開発のまとめ (2026-11)

このドキュメントは、Toucan Markdown Editor (v0.3.5 までの名前は Markdown Editor) の立ち上げから v0.2.0 までの経緯、環境構築でつまずいた点とその対処、リリース手順、残っている作業をまとめたものです。

## 1. 何を作ったか

macOS / Linux / Windows で単独で動く Markdown エディタ。Tauri 2 (Rust) + React / TypeScript + CodeMirror 6 で実装。配布物はネイティブの .app / .exe / .AppImage / .deb / .rpm で、ブラウザやサーバー、Node.js は不要。

機能の一覧とショートカットは [README](../README.md)、計画と進捗は [PLAN.md](PLAN.md) を参照。

## 3. 環境構築でつまずいた点と対処

### macOS

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `pnpm: command not found` | pnpm 未インストール | `brew install pnpm` または `npm i -g pnpm`。Node 26 以降は corepack が同梱されないので `corepack enable` は使えない |
| `cargo: command not found` (rustup 直後) | PATH が今のシェルに反映されていない | `source "$HOME/.cargo/env"` を実行するか、ターミナルを開き直す |
| `failed to run 'cargo metadata'` | 同上 | 同上 |

### Ubuntu (ヘッドレスサーバー)

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `pnpm install` が `minimumReleaseAge cutoff` で失敗 | pnpm 12 の「公開直後のパッケージを拒否する」保護。Mermaid の依存 (d3 系) が公開から 24 時間未満だった | `pnpm install --config.minimum-release-age=0`。時間が経てば不要 |
| `tauri build` の最後に `A public key has been found, but no private key` | 自動アップデート用の署名鍵が無い。パッケージ自体は生成済み | v0.2.1 以降は既定で署名ファイルを作らないので発生しない。作る場合は `TAURI_SIGNING_PRIVATE_KEY` を設定して `pnpm tauri build --config src-tauri/tauri.updater.json` |
| `apt install ./xxx.deb` の最後に `Permission denied` の Notice | apt の `_apt` ユーザーがホーム配下の .deb を読めなかった | 警告のみ。インストールは完了している |
| アプリが起動できない | SSH 接続で画面が無い | モニタ付きのデスクトップで起動するか、`DISPLAY=:0 markdown-editor` のように画面を指定する |

Linux のビルドには次のパッケージが必要: `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libayatana-appindicator3-dev libssl-dev build-essential`

## 4. リリース手順

1. `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` のバージョンを揃えて上げる
2. develop → main の PR をマージする
3. GitHub の Actions タブ → Release → Run workflow でタグ名 (`vX.Y.Z`) を入力して起動する。タグの push では起動しない (下記)
4. 4 ジョブ (macOS Apple Silicon / macOS Intel / Linux / Windows) とサーバーのジョブが完了するとドラフトリリースができる。**全ジョブの完了を待ってから** Publish する。Publish するとタグも作られる

タグの push で起動しない理由: 以前はタグでも起動していたため、Publish (= タグ作成) のたびに同じビルドがもう一度走り、公開直後のリリースのファイルを置き換えていた。v0.3.3 では手動起動のビルドと重なり、片方を取り消す必要があった。置き換えの最中はインストーラと `latest.json` の署名が一致せず、その間に更新しようとしたアプリは失敗する。

### 署名について

- **macOS**: Apple の署名用 Secrets (`APPLE_CERTIFICATE` など、README 参照) が無い場合はアドホック署名になる。初回起動時は右クリック →「開く」が必要
- **Windows**: 未署名。SmartScreen の警告が出る場合は「詳細情報」→「実行」
- **自動アップデート**: v0.3.3 から有効 (`TAURI_SIGNING_PRIVATE_KEY` を Secrets に登録済み)。リリースに `latest.json` と各インストーラの `.sig` が付き、インストール済みのアプリが起動時に更新を見つける。v0.3.2 → v0.3.3 の更新を実機で確認済み。公開鍵は `tauri.conf.json` に入っている。Secrets は登録後に読み出せないので、秘密鍵の控えは別に保管しておく。紛失した場合は `pnpm tauri signer generate` で作り直して公開鍵を貼り替える (その時点でインストール済みのアプリは一度だけ手動で入れ直し)

## 7. Web モード (v0.3.0)

「iPhone から自宅サーバー上のファイルを編集したい」という要望に応え、デスクトップ版はそのままに、同じ画面コードを HTTP サーバーから配信する入れ物を追加した。

- `crates/mde-core`: ファイル操作を Tauri 側と共有するクレート。`resolve_within` で公開フォルダ外へのアクセスを拒否
- `crates/mde-server`: axum 製の単一バイナリ。UI (dist) を rust-embed で同梱。トークン認証 (Cookie / Bearer)、`/api/{file,mtime,dir,image,raw,config}`
- `src/platform/`: UI からホスト機能を呼ぶ抽象層。Tauri 実装と Web 実装を切替
- `FilePicker`: OS ダイアログの代わりになるアプリ内ファイル選択 (開く / 名前を付けて保存)
- スマホ幅のレイアウト: 下部バー (フォルダ、アウトライン、表示切替、保存、メニュー)、サイドバーはオーバーレイ、分割表示は上下、PWA 用メタ情報とアイコン
- 検証: iPhone 14 をエミュレートした Playwright で、ログイン、ファイル一覧、プレビュー (数式 / Mermaid / 画像)、編集と保存、名前を付けて保存、未認証時のログイン画面を確認

## 7b. 編集機能の追加 (v0.3.0)

- リスト・引用の継続 (既定: Shift+Enter。設定で Enter 継続 / オフ)。番号付きリストは自動採番、空の項目で解除
- WYSIWYG 風表示 (既定オフ): カーソル行以外で見出し記号、強調、インラインコード、リンクの記号を非表示にする CodeMirror の装飾
- スマートペースト (既定: 毎回確認): 選択範囲に URL を貼ると `[選択](URL)` に。設定で常に / 確認 / オフ
- ワークスペース全文検索: `mde_core::search` (大文字小文字を区別しない部分一致、隠しフォルダと node_modules / target / dist を除外、2MB 超のファイルは対象外、500 件で打ち切り)。Tauri コマンドと `/api/search` の両方から利用。サイドバーの検索欄、Ctrl/⌘+Shift+F。フォーカスモードは Ctrl/⌘+Shift+D に移動

## 7c. サイドバーからのファイル操作 (v0.3.1)

- 各項目の「⋯」メニュー: フォルダは新規ファイル / 新規フォルダ / 名前の変更 / 削除、ファイルは名前の変更 / 削除。ヘッダーの「⋯」はルート直下への作成
- 名前の入力はアプリ内の `PromptDialog` (Tauri に標準の入力ダイアログが無いため)。拡張子なしのファイル名には `.md` を補う
- 削除: デスクトップ版は `trash` クレートで OS のゴミ箱へ、Web モードは確認のうえ完全削除 (公開フォルダ自体は不可)
- 名前変更・削除したファイルが開いている場合はタブのパスを追従 (削除時は未保存の新規文書として内容を残す)。最近使ったファイルの一覧も更新
- `treeVersion` カウンターでツリーを再読込。`mde_core::{create_dir, rename_path, delete_path}`、Tauri コマンド、`/api/{mkdir,rename,delete}`

## 7d. ドキュメント全体の整形 (v0.3.1)

- `src/editor/format.ts`: remark-parse → remark-stringify で正規化 (`-` 箇条書き、`_` / `**` 強調、フェンス付きコード、表の列幅揃え、番号の振り直し、空行と改行コードの統一、末尾改行 1 つ)。remark-frontmatter と remark-math で YAML / TOML のフロントマターと数式を保持
- ツールバー「整形」、Shift+Alt+F、スマホの「⋯」メニュー。カーソルは同じ行番号に戻す
- 注意: remark-stringify は Markdown として曖昧な文字 (行頭の `+` や `_` など) をエスケープすることがある

## 7e. 使ってみて見つかった点の修正 (v0.3.2)

| 症状 | 原因 | 修正 |
| --- | --- | --- |
| アウトラインをクリックしても、閲覧表示やスマホでは移動しない | エディタのカーソルを動かすだけで、プレビューは動かしていなかった | プレビューの各ブロックに元の行番号 (`data-line`) を付け、エディタとプレビューの両方を見出しへスクロール (`src/features/reveal.ts`)。全文検索の結果も同じ仕組み。移動中はスクロール同期を一時停止。スマホではキーボードを出さず、アウトラインを自動で閉じる |
| 開いた直後なのに編集マーク ● が付く | 改行が CRLF のファイル。エディタは内部で LF に揃えるため、元の文字列と一致せず「変更あり」と判定していた | 読み込み時に改行コードを記憶して LF で保持し、保存時に元の改行コードへ戻す (`splitEol` / `diskText`)。ファイルの改行コードは変わらない |
| サイドバーを閉じて開くと、フォルダが全部閉じる | 開閉状態をツリーの部品内に持っており、サイドバーを隠すと破棄されていた | 開いているフォルダを設定に保存 (`expandedDirs`)。再起動後も保持。別のワークスペースを開いたときはリセット |
| 前回開いていたファイルが復元されない (検証中に発見) | 起動直後の「開いているファイルを記録」処理が、復元より先に空の一覧で上書きしていた | 復元が終わるまで記録しない。復元時に無くなっていたファイルはダイアログを出さずに飛ばす |

フォーカスモードの終了方法を追加: 右上の「✕ フォーカス解除」ボタン (Esc の無いスマホ向け。それまでスマホでは終了できなかった) と、右クリックメニュー (終了、タイプライターモード切替、切り取り / コピー / 貼り付け。Shift+右クリックで通常のメニュー)。

サイドバー見出しに「◎ 開いているファイルをツリーで表示」を追加: 上位フォルダを開き、該当行までスクロールして一瞬強調する。検索結果の表示中に押すと、ツリー表示に戻る。未保存の文書やワークスペース外のファイルではその旨を表示。

チートシートをポップアップから右側のサイドパネルに変更: 開いたまま本文を編集できる。F1 / ツールバーの「？」で開閉 (Esc では閉じない)。スマホ幅では右からのオーバーレイ。

そのほか: ツリーのファイル / フォルダに未保存マーク ●、ツールバーの並びを「フォルダを開く → サイドバー → アウトライン」に変更、プレビューでフロントマターを本文として表示しないように変更、アウトラインが `===` / `---` 形式の見出しにも対応。

## 7f. 使い勝手の改善 (v0.3.2)

| 項目 | 内容 |
| --- | --- |
| 前回終了時の状態を復元 | ファイルを指定せずに起動したとき、タブ (順番・前面のタブ・ファイルごとのカーソル行)、ワークスペース、サイドバー / アウトライン / チートシートの開閉、表示モード、タイプライターモードを復元する。状態は 0.5 秒遅れで設定ファイルに書き、終了時にも書く (`src/features/session.ts`)。ファイルを指定して起動した場合はそのファイルだけを開く。スマホ幅ではパネル (重ねて表示されるもの) は開かない。設定「前回終了時の状態を復元する」でオフにできる |
| タブ切替時の位置 | タブを切り替えたとき、エディタとプレビューの両方をそのタブのカーソル位置へ戻す |
| チートシート | ポップアップをやめ、右側のサイドパネルに (F1 / ツールバーの「？」)。Esc では閉じない |
| ツリーで現在のファイルを表示 | サイドバー見出しの「◎」 |
| ツールバーの「フォルダを開く」を削除 | フォルダの選択はサイドバー見出しの 📂 (フォルダ未選択のときはサイドバー内のリンク) に一本化 |
| フォント選択 | 設定のフォントを自由入力からプルダウンに変更し、プレビューのフォントも選べるようにした。デスクトップ版は Rust (`fontdb`) でインストール済みフォントを列挙 (等幅かどうかも判定、日本語名があれば併記)。Web モードはブラウザからフォント一覧を取れないため、よく使われるフォントの候補から実際に使えるものだけを検出して表示。以前の自由入力の値はそのまま有効 |
| PDF 書き出しにスマホ用の下部バーが印刷される | 印刷時のページ幅が 768px 未満のため、スマホ用の CSS (`max-width: 767px`) が印刷にも適用されていた。`screen` に限定し、印刷時は下部バーとチートシートを非表示に |
| PDF のヘッダー・フッター | ブラウザ既定の「日付 / タイトル (… - Markdown Editor) / URL (tauri.localhost) / ページ」をやめ、`@page` のマージンボックスで「ファイル名 / 時刻 / ページ番号」だけを出す (`src/features/printPage.ts`)。Chromium はページ上端・下端にマージンボックスがあると既定のヘッダー・フッターを出さない。対象は Chromium 131 以降 (Windows の WebView2、Chrome / Edge)。macOS / Linux (WebKit) はマージンボックス非対応のため、印刷中だけタイトルをファイル名にする対応のみ |

## 7g. 利用者目線での見直し (v0.3.2)

実際に操作しながら「使っていて引っかかる所」を探して直した。

| 見つけた点 | 対応 |
| --- | --- |
| 未保存の変更の確認が 2 段階 (保存しますか → 破棄しますか) で、Web モードではブラウザ標準の「OK / キャンセル」しか出ず、どちらが何か分からない | アプリ内ダイアログ 1 つに「キャンセル / 保存しない / 保存する」を表示 (`ConfirmDialog.tsx`)。Web モードの確認・通知もすべてこのダイアログにして、呼び出し側が指定したボタン名 (「削除する」など) が出るようにした |
| 入力し続けている間、プレビューが止まったままになる。タブを切り替えた直後も、前のタブの内容が一瞬残る | タブ切替時は待たずに描画。入力中も一定間隔 (通常 0.5 秒、重い文書では描画時間の 4 倍) で追従 |
| 検索・置換パネルが英語で、文字もボタンも小さい | 日本語化し、大きさを調整 |
| デスクトップ版で、ファイルをウィンドウにドロップしても何も起きない (README には画像のドラッグ&ドロップ対応と書いてあった) | Tauri はファイルのドロップをページに渡さず独自のイベントで通知するため、それを受けるようにした。Markdown はタブで開く、画像はドロップ位置に挿入 (`import_image` コマンドで `assets/` にコピー)、フォルダはワークスペースとして開く。**実機での確認は未実施** (仮想ディスプレイではドラッグ操作を再現できないため) |
| カーソルが何行目・何列目か分からない | ステータスバーに表示。選択中は文字数も表示 |
| 新規ドキュメントを保存するとき、毎回 `untitled.md` から名前を打ち直す | 最初の見出し (なければ最初の行) からファイル名を提案。ワークスペースを開いていればそのフォルダを初期位置に |
| 同じ名前のファイル (README.md など) を複数開くと、タブで見分けがつかない | 名前が重なるタブだけ「README.md — フォルダ名」と表示 |
| プレビューのタスクリストがクリックできない | チェックボックスをクリックすると元の Markdown の `[ ]` / `[x]` を書き換える (元に戻す操作も効く) |
| プレビューで見ている箇所がソースのどこか探しにくい | プレビューをダブルクリックすると、エディタのカーソルがその行へ移動 |
| 他のプログラムで作ったファイルがツリーに出てこない (↻ を押す必要があった) | ウィンドウに戻ってきたときにツリーを自動で読み直す |
| 何も書いていないとき、何をすればよいか分からない | 空のエディタに案内文を表示 |
| 同じタイミングで複数の画像を保存すると、ファイル名が重なって上書きされる可能性 | 重なったら連番を付ける |

## 7h. 英語 UI (v0.3.3)

- 画面の文言は `t("日本語の文")` で書き、英語は `src/i18n/en.ts` の辞書 (日本語の文 → 英語) から引く。日本語がそのままソースに残るので読みやすく、辞書に無い文は日本語のまま表示される。差し込みは位置指定 (`t("{0} 行目", line)`)
- 言語は設定の「言語 / Language」(OS に合わせる / 日本語 / English)。既定は OS に合わせる (ブラウザ / WebView の優先言語が日本語なら日本語、それ以外は英語)。切り替えは再起動なしで反映され、エディタの検索パネルと案内文も切り替わる
- `t()` はモジュールの読み込み時ではなく、描画時やイベント処理の中で呼ぶこと (読み込み時に呼ぶと起動時の言語で固定される)。一覧データは関数にしてある (`viewModes()`, `syntaxRows()` など)
- 文を部品に分けて連結しない (削除の確認は 4 通りの完全な文にした)
- Rust 側 (デスクトップのコマンドと Web サーバー) のエラー文は日本語のまま返し、画面側の `tError()` が「: 」より前の既知の部分を英語に置き換える
- `src/__tests__/i18n.test.ts` が、ソース中の `t()` の文字列すべてに英語訳があること、差し込み位置が両言語で一致することを検査する。文言を足したら `en.ts` にも足す (足し忘れるとテストが落ちる)
- 英語になっていないもの: README と `docs/`、Web サーバーの起動時メッセージとインストールスクリプト (ターミナルに出るもの)

## 7i. 設定の保存 / キャンセル (v0.3.4)

- 設定画面での変更は、これまでどおりその場で画面に反映する (プレビュー)。ただし記録されるのは「保存」を押したときだけ。「キャンセル」、×、Esc、画面外のクリック、ショートカットでの閉じ方はすべて、保存済みの値に戻す
- 仕組み (`src/store/useSettings.ts`): `preview()` はストアの値だけを変え、変更前の値を「未保存の一覧」に控える。`commitPreview()` で一覧を空にして書き込み、`cancelPreview()` で控えた値に戻す
- 設定ファイルには、最近使ったファイルやセッション (開いているタブなど) も入っていて、こちらは設定画面を開いている間も随時書き込まれる。そのときに未保存の設定が一緒に書かれないよう、書き込み時は「未保存の一覧」にある項目を保存済みの値に差し替える

「URL を選択範囲に貼り付けたとき」の設定 (常にリンク / 毎回確認 / そのまま貼り付け) が、どれを選んでも「確認なしでリンクにする」になっていた。`@codemirror/lang-markdown` の `markdown()` が標準で `pasteURLAsLink` (選択中の文字に URL を貼るとリンクにする) を含んでおり、こちらの貼り付け処理より先に動いていたため。`markdown({ pasteURLAsLink: false })` で止め、差分表示の編集側にも同じ貼り付け処理を入れた。3 つの設定それぞれの動作を画面テストに追加。

教訓: エディタの拡張が標準で持っている動作と、自前の設定がぶつかることがある。「既定の設定で期待どおりに見える」だけでは確認にならないので、設定の全部の値で動作を確かめる。

## 7r. CI の重複をなくす (v0.3.7 のあと)

1 回の変更で CI が 6 ジョブ走っていた (3 つの OS × 「develop へのプッシュ」と「PR」の 2 回)。同じコミットを 2 回確かめているだけなので、プッシュで走らせるのは `main` だけにし、`develop` の変更は PR の実行で確かめる (3 ジョブ)。同じ PR に続けてプッシュしたときは、古いコミットの実行を自動で取り消す (`concurrency`)。

注意: PR を開いていない状態で `develop` にプッシュしただけでは CI は走らない。`main` 向けの PR を開いた時点で走る。

## 7s. 整形で URL が `<>` で囲まれる (v0.3.7 のあと)

「整形」を実行すると、そのまま書いた URL (`https://example.com`) が `<https://example.com>` に、`www.example.com` が `[www.example.com](http://www.example.com)` に書き換わっていた。意味は同じ (どちらもリンク) だが、書いた人が打った形ではない。パーサーが裸の URL をリンクとして読み、書き出すときにリンクの記法へ直していたのが原因。`src/editor/format.ts` の `keepBareUrls` で、元の文で `<` や `[` から始まっていないリンクは元の文字のまま書き出すようにした。`<...>` や `[...](...)` で書いたリンクは従来どおり。

あわせて、整形での表の列幅を表示幅でそろえるようにした (全角文字を 2 桁として数える。これまでは日本語を含む表で縦の線がずれていた)。

この件をきっかけに、整形を「前後で意味 (構文木) が同じか」「2 回かけても変わらないか」で約 45 種類の書き方 + このリポジトリの文書で調べ直し、次も直した。

| 問題 | 例 | 対処 |
| --- | --- | --- |
| 日本語の文中の強調が文字コードになる | `これは*強調*です` → `これ&#x306F;_&#x5F37;&#x8ABF;_&#x3067;す` | 強調の記号を `_` から `*` に変更。`_` は文字に隣接すると強調にならない (日本語ではほぼ常に隣接する) ため、書き出し側が前後の文字を文字コードに変えていた |
| 不要なバックスラッシュが足される | `[要確認]` → `\[要確認]`、`9:00~18:00` → `9:00\~18:00`、`C#` → `C\#`、URL 中の `(` `)` | 書き出したあと、取り除いても意味が変わらないバックスラッシュだけを外す (1 つずつ構文木を比べて確かめる)。必要なもの (`\*強調ではない*`、行頭の `\#` など) は残る |
| 行末スペース 2 つの改行が `\` に変わる | `一行目␣␣` → `一行目\` | 書いた人の書き方 (スペース 2 つ / バックスラッシュ) を保つ。チートシートで案内しているのはスペース 2 つのほう |
| 上の対処のあと表の縦線が 1 文字ずれる | — | 最後に表をそろえ直す (エディタの「列幅を整える」と同じ処理) |

テスト `src/__tests__/formatAudit.test.ts` に、この確認 (意味が変わらない / 2 回かけても同じ / 文字コードが出ない) をそのまま残した。

意図どおりのまま残したもの: `+` や `*` の箇条書き → `-`、`__太字__` → `**太字**`、`1)` → `1.`、番号の振り直し、`===` 下線の見出し → `#`、`~~~` や字下げのコード → ```` ``` ````、`***` → `---`、表の列幅、連続する空行と行末の空白の削除。

未対応: 1 つの段落に `~` が 2 つあると (例: `9:00~18:00、約10~20人`)、Markdown の仕様 (GFM) でその間が取り消し線になる。プレビューでも取り消し線で表示され、整形すると `~~` に書き換わる。日本語では範囲の「~」としてよく使うので、取り消し線は `~~` だけにする変更を検討する余地がある。

### ライセンスと公開範囲

- OSS ライセンスは付けていない (`LICENSE` に All rights reserved と明記、`package.json` は `"license": "UNLICENSED"`)。MIT などは一度付けて公開すると取り消せないため、公開を続けると決めるまでは付けない。付ける場合は `LICENSE` を差し替え、README と `package.json`、`src-tauri/tauri.conf.json` の `bundle.copyright` を合わせて直す
- リポジトリを private に戻すと、(1) GitHub Actions が無料枠の制限に戻る、(2) リリースのダウンロード URL が外から見えなくなり、インストール済みアプリの自動アップデート (`latest.json` の取得) も動かなくなる
